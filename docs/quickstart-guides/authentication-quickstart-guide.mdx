# Sign up and authenticate

To gain access to IQM's API and its services, you must first sign up and log in to obtain the authentication required to send requests.


The IQM platform uses [bearer authentication<ExternalLink />](https://swagger.io/docs/specification/v3_0/authentication/bearer-authentication/) tokens to authenticate along with an **Organization Workspace ID**. 

   * Sign up and log in both return an access token and a <var>refresh token</var>. The access token remains valid for 24 hours. After that, use the refresh token to get a new access token.
   * Every API call also needs your **Organization Workspace ID** (<var>owId</var>) in the <var>X-IAA-OW-ID</var> header. The sign-up response includes it. After logging in, use [Get list of accessible Organizations](/guidelines/workspace-api#get-list-of-accessible-organizations) to find the Organization Workspace IDs that you have access to.

## Client ID and Client Secret

Before you can sign up or log in with the IQM API, you need to request a Client ID and Client Secret by emailing [support@iqm.com<ExternalLink />](mailto:support@iqm.com). Once you have obtained these credentials, they are used as the header authorization for signing up and logging in. Send them in the <var>Authorization</var> header as <var>Basic</var> followed by the Base64 encoding of <var>client_id:client_secret</var>. To log in or refresh a token, you can instead send <var>client_id</var> and <var>client_secret</var> as form fields in the request body.

Read more about Client ID and Secret at [OAuth<ExternalLink />](https://www.oauth.com/oauth2-servers/client-registration/client-id-secret/).

## Sign up

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/sign-up" />

<div class="endpoint-container">
  <div class="child1">

Complete an invitation by setting the invited user's password. This endpoint doesn't create new accounts. A user must first be invited to a workspace, and the link in the invitation email carries the <var>inviteHash</var>. To get an account, ask your workspace owner to invite you or contact [support@iqm.com<ExternalLink />](mailto:support@iqm.com).

The response logs the user in, with the same tokens as [Log in](#log-in) plus the user's <var>owId</var>. If the workspace has a redirect URL configured, the response also includes <var>redirectionUrl</var>, that URL with the user's tokens filled in.

| Headers |  |
| ---- | --- |
| `Authorization` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>Basic</var> followed by your Base64-encoded <var>client_id:client_secret</var>. |
| `Content-Type` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>application/json</var>. |

| Request Schema |  |
| ---- | --- |
| `email` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Email address of user. |
| `password` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Desired password of user. |
| `inviteHash` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Invitation hash from the link in the user's invitation email. |

## Log in

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/oauth/token" />

<div class="endpoint-container">
  <div class="child1">

Once your account is set up, you can log in. This API accepts a URL encoded form with the user's email and password. Using your Client ID and Client Secret in the header, you can authenticate and log in.

The response includes an access token and a refresh token.

To find the Organization Workspace IDs that you have access to, use [Get list of accessible Organizations](/guidelines/workspace-api#get-list-of-accessible-organizations).


<OAuthHeaders />

| Request Schema |  |
| ---- | --- |
| `grant_type` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>password</var> for login. <br />See [OAuth Grant Types<ExternalLink />](https://oauth.net/2/grant-types/). |
| `username` <br /><span class="type-text">string</span> <span class="required-text">required</span> | User account email. |
| `password` <br /><span class="type-text">string</span> <span class="required-text">required</span> | User account password. |

</div><div class="child2">

<Tabs>
<TabItem value="JSON" label="JSON" default>

```curl title="Request sample"
curl -i --location 'https://api.iqm.com/api/v3/ua/oauth/token' \
--header 'accept: application/json, text/plain, */*' \
--header 'Authorization: Basic <base64 of client_id:client_secret>' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'grant_type=password' \
--data-urlencode 'username=user@iqm.com' \
--data-urlencode 'password=<your password>'
```

```json title="Response 200"
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCIgOiAiSldUIn0...",
  "refresh_token": "eyJhbGciOiJIUzUxMiIsInR5cCIgOiAiSldUIn0...",
  "scope": "read write",
  "token_type": "bearer",
  "expires_in": 86399
}
```

## Refresh token

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/oauth/token" />

<div class="endpoint-container">
<div class="child1">

Use a refresh token to get a new access token. This endpoint accepts a URL encoded form with the refresh token. Using your Client ID and Client Secret in the header, you can authenticate and get a new access token.

<OAuthHeaders />

| Request Schema | |
| --- | --- |
| `grant_type` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>refresh_token</var> to get a new access token. <br />See [OAuth Grant Types<ExternalLink />](https://oauth.net/2/grant-types/). |
| `refresh_token` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Refresh token from the login response. |

</div>
<div class="child2">

```curl title="Request sample"
curl -i --location 'https://api.iqm.com/api/v3/ua/oauth/token' \
--header 'accept: application/json, text/plain, */*' \
--header 'Authorization: Basic <base64 of client_id:client_secret>' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'grant_type=refresh_token' \
--data-urlencode 'refresh_token=<your refresh token>'
```

```json title="Response 200"
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCIgOiAiSldUIn0...",
  "refresh_token": "eyJhbGciOiJIUzUxMiIsInR5cCIgOiAiSldUIn0...",
  "scope": "read write",
  "token_type": "bearer",
  "expires_in": 86399
}
```
