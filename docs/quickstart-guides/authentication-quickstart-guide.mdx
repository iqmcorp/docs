# Sign up and authenticate

To gain access to IQM's API and its services, you must first sign up and log in to obtain the authentication required to send requests.


The IQM platform uses [bearer authentication<ExternalLink />](https://swagger.io/docs/specification/v3_0/authentication/bearer-authentication/) tokens to authenticate along with an **Organization Workspace ID**. 

   * On sign up, a <var>bearer token</var> is returned in the response along with a <var>refresh token</var>. The access token remains valid for 24 hours, at which time the refresh token must be used to retrieve a new access token. 
   * On log in, an **Organization Workspace ID** (<var>owId</var>) is returned in the response. This ID is required for all API calls and to authenticate your access to the platform.

## Client ID and Client Secret

Before you can sign up or log in with the IQM API, you need to request a Client ID and Client Secret by emailing [support@iqm.com<ExternalLink />](mailto:support@iqm.com). Once you have obtained these credentials, they are used as the header authorization for signing up and logging in. The header is formed like this: <var>client_id:client_secret base64</var>.

Read more about Client ID and Secret at [OAuth<ExternalLink />](https://www.oauth.com/oauth2-servers/client-registration/client-id-secret/).

## Sign up

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/sign-up" />

<div class="endpoint-container">
  <div class="child1">

Sign up for an account by providing an email address and desired password.

| Headers |  |
| ---- | --- |
| `Authorization` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>Basic</var> followed by your Base64-encoded <var>client_id:client_secret</var>. |
| `Content-Type` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>application/json</var> |

| Request Schema |  |
| ---- | --- |
| `email` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Email address of user |
| `password` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Desired password of user |
| `inviteHash` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Invitation hash from the link in the user's invitation email |

## Log in

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/oauth/token" />

<div class="endpoint-container">
  <div class="child1">

Once you have created an account, you can log in. This API accepts a URL encoded form with the user's email and password. Using your Client ID and Client Secret in the header, you can authenticate and log in.

The response includes an access token, refresh token, and the Organization Workspace ID. These credentials are used to maintain your session and authenticate your access to the IQM platform.


<OAuthHeaders />

| Request Schema |  |
| ---- | --- |
| `grant_type` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>password</var> for login <br />[OAuth Grant Types<ExternalLink />](https://oauth.net/2/grant-types/) |
| `username` <br /><span class="type-text">string</span> <span class="required-text">required</span> | User account email |
| `password` <br /><span class="type-text">string</span> <span class="required-text">required</span> | User account password |

</div><div class="child2">

<Tabs>
<TabItem value="JSON" label="JSON" default>

```curl title="Request sample"
curl -i --location 'https://api.iqm.com/api/v3/ua/oauth/token' \
--header 'accept: application/json, text/plain, */*' \
--header 'Authorization: Basic <Client ID/Client Secret>' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'grant_type=password' \
--data-urlencode 'username=user@iqm.com' \
--data-urlencode 'password=<your password>'
```

```json title="Response 200"
{
    "success": true,
    "data": {
        "access_token": "106adb25-37b0-4cab-8381-d682fe7cc3c8",
        "refresh_token": "eac4c1f6-781e-4b04-baff-9c2e415d1f64",
        "scope": "read write",
        "token_type": "bearer",
        "expires_in": 35999,
        "owId": 200001
    }
}
```

</TabItem></Tabs>

</div></div>

## Refresh token

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/oauth/token" />

<div class="endpoint-container">
<div class="child1">

Use a refresh token to get a new access token. This endpoint accepts a URL encoded form with the refresh token. Using your Client ID and Client Secret in the header, you can authenticate and get a new access token.

<OAuthHeaders />

| Request Schema | |
| --- | --- |
| `grant_type` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>refresh_token</var> to get a new access token<br />[OAuth Grant Types<ExternalLink />](https://oauth.net/2/grant-types/) |
| `refresh_token` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Refresh token |

</div>
<div class="child2">

```curl title="Request sample"
curl -i --location 'https://api.iqm.com/api/v3/ua/oauth/token' \
--header 'accept: application/json, text/plain, */*' \
--header 'Authorization: Basic <Client ID/Client Secret>' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'grant_type=refresh_token' \
--data-urlencode 'refresh_token=eac4c1f6-781e-4b04-baff-9c2e415d1f64'
```

```json title="Response 200"
{
  "access_token": "106adb25-37b0-4cab-8381-d682fe7cc3c8",
  "refresh_token": "eac4c1f6-781e-4b04-baff-9c2e415d1f64",
  "scope": "read write",
  "token_type": "bearer",
  "expires_in": 35999
}
```

</div>
</div>
