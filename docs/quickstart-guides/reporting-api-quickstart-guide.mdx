## About IQM reports

IQM's APIs provide access to all dimensions and KPIs of your ad-serving reporting data in JSON format. With the Reports API you can create a customized report with your desired dimensions and metrics.

Reports can be either **daily** or **aggregated**. The daily report includes the date as a dimension and provides the data breakdown by date. Reports provide five top-level dimensions of filtering support, and you can filter on multiple values for each dimension.

You can run a report covering up to 365 days of data for any dimension combination. You must run multiple reports if you need more than that.

## Run a report using the IQM API

This quickstart guide covers how to run a basic IQM report.  

The minimum requirements to perform this task are: logging in with authentication credentials, selecting dimensions and metrics, choosing a timezone, and executing a report. Once these steps are accomplished, more can be learned about IQM's API through the [guidelines](/guidelines/) pages.

1. Log in
      * Optional if you have already logged in and have a token
1. Request dimensions and metrics
      * Optional if you know supported/desired dimensions/metrics
1. Request timezones
      * Optional if you already know supported/desired ID values
1. Execute the report
      * Execute the report with parameters from the previous steps

### Step 4: Execute a report

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ra/report/execute" />

<div class="endpoint-container">
  <div class="child1">

Run a report based on report data.

A start date and end date are required, and the range can be at most 365 days.

Include at least one dimension in <var>dimensions</var> and at least one metric in <var>columns</var>. Dimensions are not valid as columns.

For further information see [Execute a report](/guidelines/reports-api#execute-a-report).

<ApiHeaders />


| Request schema  |  |
| ---- | --- |
| `startDate` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Unix epoch timestamp of start date, in milliseconds |
| `endDate` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Unix epoch timestamp of end date, in milliseconds |
| `dimensions` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Dimensions for the report as a JSON-encoded array of objects, each with a <var>filter</var> (a dimension key from the dimensions and metrics details API) and an optional <var>value</var> array of IDs that limits rows to those dimension values, serialized as a string (see the request sample) |
| `customerIds` <br /><span class="type-text">array of integers</span> | List of Customer IDs to include in the report, leave empty array [ ] to include all, optional for Workspace users only |
| `columns` <br /><span class="type-text">array of strings</span> <span class="required-text">required</span> | List of metrics for the report obtained from dimensions and metrics details API |
| `timezoneId` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Timezone ID |
| `requestType` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Time breakdown of the report rows: daily (<var>1</var>), aggregated with no time breakdown (<var>2</var>), weekly (<var>3</var>), or monthly (<var>4</var>) |
| `reportAggregated` <br /><span class="type-text">string</span> <span class="required-text">required</span> | String <var>"0"</var> or <var>"1"</var>. <br /><EnumWidget values={reportAggregated} /> |
|`timezoneName` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Timezone name, e.g. <var>US/Eastern</var> |
| `filters` <br /><span class="type-text">object</span> | Optional extra filters: <var>campaignIds</var>, <var>creativeTypeIds</var>, and <var>campaignStatuses</var> arrays |
| `pageNo` <br /><span class="type-text">integer</span> | Page number of retrieved data |
| `noOfEntries` <br /><span class="type-text">integer</span> | Number of entries returned per page |
| `sortBy` <br /><span class="type-text">string</span> | Sorts by ascending (+) or descending (-), example: <var>-impressions</var> |
