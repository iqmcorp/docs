# Schedule a report

Create your first report schedule using IQM's API in this step-by-step quickstart guide.

Get started scheduling a report with the following endpoints:

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/oauth/token" />
<br /><CopyUrl method="POST" url="https://api.iqm.com/api/v3/ra/report/add" />
<br /><CopyUrl method="POST" url="https://api.iqm.com/api/v3/ra/report/email/schedule" />


## About IQM reports

The IQM APIs provide access to all dimensions and KPIs of ad-serving reporting data in JSON format.

Reports can be either **daily** or **aggregated**. The daily report includes the date as a dimension and provides the data breakdown by date. Reports provide five top-level dimensions of filtering support, and can be filtered for multiple values in each dimension.

A report can cover up to 365 days of data for any dimension combination. Run multiple reports if you need more than that.

## Schedule a report

This quickstart guide covers how to schedule a report. 

The minimum requirements to perform this task are: logging in with authentication credentials, and having a campaign started in order to execute reports. Once these steps are accomplished, more can be learned about IQM's API through the [guidelines](/guidelines/) pages.

1. Log in
    * Optional if you have already logged in and have a token
1. Save a report
    * Skip this step if you already have a saved report and its ID
1. Schedule a report
    * Execute scheduling event with frequency, day, and end date parameters

### Step 1: Log in

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ua/oauth/token" />

### Step 2: Save a report

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ra/report/add" />

<div class="endpoint-container">
  <div class="child1">

A schedule is attached to a saved report, so save the report first. The response's <var>data</var> is the new report's ID; use it as <var>reportId</var> in the next step.

For further information see [Create report](/guidelines/reports-api#create-report).

| Request schema |  |
|---|---|
| `reportName` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Name of the report |
| `startDate` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Unix epoch timestamp of start date, in milliseconds |
| `endDate` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Unix epoch timestamp of end date, in milliseconds. The range can be at most 365 days. |
| `dimensions` <br /><span class="type-text">string</span> <span class="required-text">required</span> | JSON-encoded array of dimensions, for example <var>[\{"filter":"campaign"\}]</var>. Add a <var>value</var> array to a dimension to filter by its IDs. |
| `columns` <br /><span class="type-text">array of strings</span> <span class="required-text">required</span> | Metrics to include, such as <var>impressions</var> and <var>clicks</var>. Dimensions go in <var>dimensions</var>, not here. |
| `requestType` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | <var>1</var>: daily, <var>2</var>: aggregated, <var>3</var>: weekly, <var>4</var>: monthly |
| `reportAggregated` <br /><span class="type-text">string</span> <span class="required-text">required</span> | <var>"0"</var> or <var>"1"</var>. See [Execute a report](/guidelines/reports-api#execute-a-report). |
| `timezoneId` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | [Timezone ID](/guidelines/master-api#get-timezones) |
| `timezoneName` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Timezone name, for example <var>US/Eastern</var> |

</div><div class="child2">

### Step 3: Schedule a report

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/ra/report/email/schedule" />

<div class="endpoint-container">
  <div class="child1">

Use the <var>reportId</var> from Step 2 and decide the delivery frequency, day, and end date of scheduled reports. This API saves the delivery information and returns a success message.

For further information see [Scheduling management](/guidelines/reports-api#scheduling-management).

| Request schema |  |
|---|---|
| `reportId` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | The unique report ID, event is created on this report ID |
| `subscriberEmails` <br /><span class="type-text">array of strings</span> <span class="required-text">required</span> | List of emails to which the report is sent |
| `fileType` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | [Report file type ID](/guidelines/reports-api#get-report-file-types). The report is sent in the selected file format. <br /><EnumWidget values={reportFileTypes} /> |
| `deliveryFrequency` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | [Delivery frequency type ID](/guidelines/reports-api#get-report-delivery-frequency-types) for the emails to be sent. <br /><EnumWidget values={reportDeliveryFrequency} /> <br /><var>1</var> (one time now) emails the report right away and removes any schedule already saved on the report. |
| `deliveryDay` <br /><span class="type-text">string</span> | [<span class="required-text">Required</span> if <var>deliveryFrequency</var> is weekly or monthly] Day when the report is sent (not case-sensitive). <br />Weekly: <var>Sunday</var>, <var>Monday</var>, ... <br />Monthly: <var>First</var>, <var>Last</var>, or a day of the month <var>1</var> to <var>28</var> |
| `eventEndDate` <br /><span class="type-text">integer</span> | [<span class="required-text">Required</span> if <var>deliveryFrequency</var> is daily, weekly, or monthly] Unix epoch timestamp in milliseconds; must be in the future. This is event's end date, the scheduled report is stopped after the <var>eventEndDate</var> is exceeded. |
| `runningTotalEnabled` <br /><span class="type-text">boolean</span> <span class="required-text">optional</span> | Flag to indicate if the 'Total' Running is enabled for the report. This flag is supported only with 'Campaign' dimension. If this is true the start-date for the report duration should be the EARLIEST campaign start date, so the report-time-period will be from the earliest-campaign-start-date to the report-end-date. |
| `earliestCampaignStartDate` <br /><span class="type-text">integer</span> | [<span class="required-text">Required</span> with <var>runningTotalEnabled</var> as <var>true</var>] Unix epoch timestamp, in milliseconds. This is campaign's EARLIEST start date from the selected campaigns, which is set as the start date of the report-time-period. |

</div><div class="child2">
