## About Political proposals

A Political proposal is a forecast-backed media plan that IQM can turn into a live IO and campaigns. Proposals are built in stages, and each stage produces the ID that the next one needs:

**Plan → Strategy → Proposal → Insertion order and campaigns**

  * A **plan** holds the budget, flight dates, and targeting. A plan is saved as either a draft or ready plan. Only ready plans produce strategies.
  * When a ready plan is created, IQM's forecasting service generates up to three **strategies** for it: Maximum Reach, Balanced, and Most Economical. Each strategy is a different trade-off between reach, impressions, and cost.
  * **Activating** a strategy turns it into a **proposal**: an editable set of proposed campaigns with its own status.
  * **Generating an IO** from a ready proposal creates a real IO and campaigns in your Workspace. This is a one-way step.

## Before you begin

To create a Political proposal and convert it into an IO, the following are required:

  * An account on the IQM platform in a Political Workspace
    * See the [Getting started](/getting-started/before-you-begin) section to create an account and request a Client ID and Client Secret.
    * Planner API requests from a Workspace outside the Political vertical are rejected.
  * A Political Advertiser profile
    * See [Get list of Advertiser profile and details](/guidelines/workspace-api#get-list-of-advertiser-profile-and-details) to find an existing profile ID, or [Add Advertiser profile](/guidelines/workspace-api#add-advertiser-profile) to create one.
    * Required in [Step 5](#step-5-generate-an-io-and-campaigns) to generate an IO. Use a real profile ID; it is validated when the IO is created.

## Create a Political proposal

This tutorial covers the standard path for Reach forecasting and Budget estimation plans:

1. Create a ready plan
1. Get the plan's strategies
1. Activate a strategy into a proposal
1. Check proposal details
1. Generate an IO and campaigns

Voter TV+ (cross-screen) plans follow a different path. See [Voter TV+ proposals](#voter-tv-proposals) after completing the standard path. To target a Custom Voter audience (CVA), see [Target a Custom Voter audience](#target-a-custom-voter-audience) before Step 1.

### Step 2: Get the plan's strategies

<CopyUrl method="GET" url="https://api.iqm.com/api/v3/plan/political/strategies" operationId="getPoliticalStrategyListing" />

<div class="endpoint-container">
  <div class="child1">

Use the <var>planId</var> from Step 1 to list the strategies generated for the plan. Compare the forecasted <var>reach</var>, <var>impressions</var>, <var>budget</var>, and <var>cpm</var> of each strategy and save the <var>id</var> of the one you want to activate in Step 3.

A strategy's <var>budget</var>, <var>frequency</var>, creative types, and campaigns are the forecasting service's recommendation, not a copy of the plan. They can differ from what you sent in Step 1: for example, a lower budget, a lower frequency cap, or only some of the plan's creative types. The forecasting service can also return fewer than three strategies.

:::caution

If you create extra strategies with [Generate custom strategies](/political-vertical/planner#generate-custom-strategies), the <var>id</var> in that endpoint's response is the forecasting service's own ID, not an IQM strategy ID, and can't be activated. Always get strategy IDs from this endpoint.

:::

## Voter TV+ proposals

Voter TV+ (objective <var>3</var>) plans forecast reach across linear TV and connected TV (CTV). They follow a different path from the standard steps above:

1. Get a reach saturation graph
1. Create a ready plan with the graph
1. Activate the plan into a proposal
1. Split the proposal's CTV campaigns (optional)
1. Generate an IO and campaigns, as in [Step 5](#step-5-generate-an-io-and-campaigns) of the standard path

When the IO is generated, only the CTV proposed campaigns become campaigns; linear TV campaigns aren't created.

### Eligibility requirements

Voter TV+ plans:

  * Must have a flight of 7 to 31 days
  * Must have a budget over <var>100</var>
  * Can't target [Power Segment audiences](/political-vertical/audience-segments#power-segment-audience-details)

### Step 1: Get a reach saturation graph

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/plan/political/reach-saturation-graph" operationId="getCrossScreenGraph" />

<div class="endpoint-container">
  <div class="child1">

Send the plan's budget, dates, and targeting with <var>objectiveId</var> <var>3</var> to get a reach forecast for linear TV and CTV. Save the <var>graphId</var> and <var>overview</var> from the response for the next step.

Check <var>audienceOverlap.totalReach</var> in the response before continuing. If it's <var>0</var>, the targeting doesn't match any voters: a plan created from this graph produces a proposal with <var>0</var> budgets, and splitting it fails. Narrow the location targeting, for example to states or DMAs, and request a new graph. The sample targets Ohio (<var>30200036</var>) and Pennsylvania (<var>30200039</var>).

### Step 3: Create CVA details

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/plan/political/cva-details" operationId="createCvaDetails" />

<div class="endpoint-container">
  <div class="child1">

Define the CVA with an equation of the taxonomy IDs from Step 1, and the reach from Step 2.

Equation syntax:
  * Wrap each segment ID in parentheses
  * Separate segments with <var>|</var> to combine them (OR)
  * Separate groups with <var>&</var> to intersect them (AND)

For example, <var>((IQMCVACA069112|(IQMCVACA080323))&(IQMCVACA101616))</var> targets voters in either of the first two segments who are also in the third.

An equation with an unknown taxonomy ID or unbalanced parentheses returns a <var>500</var> error with the message <var>Invalid CVA details provided</var>. This is a validation error, not an outage: fix the equation and try again.

| Request schema |  |

## Restore an expired proposal

<CopyUrl method="PATCH" url="https://api.iqm.com/api/v3/plan/political/proposals/restore" operationId="restoreProposals" />

<div class="endpoint-container">
  <div class="child1">

A proposal that isn't converted becomes <var>Expired</var> (<var>3</var>) after its end date passes. To use an expired proposal again, restore it with new flight dates. Restored proposals return to <var>Ready</var> (<var>6</var>) status and can then be converted as in [Step 5](#step-5-generate-an-io-and-campaigns).

The new flight can be a different length from the original; unlike generating an IO, restoring doesn't require the duration to stay the same. Restoring only works on expired proposals. It isn't an undo for [Delete proposals](/political-vertical/planner#delete-proposals).

| Request schema |  |
| ---- | --- |
| `proposalIds` <br /><span class="type-text">array of integers</span> <span class="required-text">required</span> | IDs of expired proposals to restore. |
| `startTime` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | New Unix epoch start time in milliseconds; can't be in the past. |
| `endTime` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | New Unix epoch end time in milliseconds; must be at least 30 minutes after <var>startTime</var>. |
