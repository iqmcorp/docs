## About Political proposals

A Political proposal is a forecast-backed media plan that IQM can turn into a live IO and campaigns. Proposals are built in stages, and each stage produces the ID that the next one needs:

**Plan → Strategy → Proposal → Insertion order and campaigns**

  * A **plan** holds the budget, flight dates, and targeting. A plan is saved as either a draft or ready plan. Only ready plans produce strategies.
  * When a ready plan is created, IQM's forecasting service generates up to three **strategies** for it: Maximum Reach, Balanced, and Most Economical. Each strategy is a different trade-off between reach, impressions, and cost.
  * **Activating** a strategy turns it into a **proposal**: an editable set of proposed campaigns with its own status.
  * **Generating an IO** from a ready proposal creates a real insertion order and campaigns in your workspace. This is a one-way step.

A proposal moves through the following statuses. See [Proposal status list](/guidelines/planner-api#proposal-status-list) for details.

## Before you begin

To create a Political proposal and convert it into an IO, the following are required:

  * An account on the IQM platform in a Political workspace
    * See [Getting started](/getting-started/before-you-begin) section to create an account and request a Client ID and Client Secret
    * Planner API requests from a workspace outside the Political vertical are rejected with <var>Request for forbidden vertical</var>
  * A Political Advertiser profile
    * See [Get list of Advertiser profile and details](/guidelines/workspace-api#get-list-of-advertiser-profile-and-details) to find an existing profile ID, or [Add Advertiser profile](/guidelines/workspace-api#add-advertiser-profile) to create one
    * Required in [Step 6](#step-6-generate-an-io-and-campaigns) to generate an IO. Use a real profile ID; it is validated when the IO is created.

## Create a Political proposal using the IQM API

This tutorial covers the standard path for Reach forecasting and Budget estimation plans:

1. Log in
    * Optional if you have already logged in and have a token
1. Create a ready plan
1. Get the plan's strategies
1. Activate a strategy into a proposal
1. Check proposal details
1. Generate an IO and campaigns

Voter TV+ (cross-screen) plans follow a different path. See [Voter TV+ proposals](#voter-tv-proposals) after completing the standard path. To target a Custom Voter Audience, see [Target a Custom Voter Audience](#target-a-custom-voter-audience) before Step 2.

### Step 2: Create a ready plan

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/plan/political/plans/ready" operationId="createReadyPlan" />

<div class="endpoint-container">
  <div class="child1">

Create a ready plan with a budget, flight dates, and targeting. When a ready plan is created, IQM sends its details to the forecasting service, which generates the plan's strategies. Save the <var>planId</var> from the response for Step 3.

To save an incomplete plan without generating strategies, use <span class="code-text">POST /api/v3/plan/political/plans/draft</span> instead. See [Create plan](/political-vertical/planner#create-plan).

| Request schema |  |
| ---- | --- |
| `name` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Plan name, up to 255 characters |
| `objectiveId` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | [Plan objective ID](/political-vertical/planner#get-plan-objectives) <br /><EnumWidget values={planObjectives} /> <br />Use <var>1</var> or <var>2</var> for this tutorial. Voter TV+ (<var>3</var>) follows the [Voter TV+ path](#voter-tv-proposals). |
| `totalBudget` <br /><span class="type-text">number</span> <span class="required-text">required</span> | Total plan budget |
| `details` <br /><span class="type-text">object</span> <span class="required-text">required</span> | Flight dates, frequency cap, and margin |
| `details.startDate` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Unix epoch start date in milliseconds; can't be in the past |
| `details.endDate` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | Unix epoch end date in milliseconds; must be at least 30 minutes after <var>startDate</var> |
| `details.frequencyCap` <br /><span class="type-text">integer</span> | Frequency cap, <var>1</var> to <var>999</var> |
| `details.marginValue` <br /><span class="type-text">integer</span> | Margin applied on top of the base CPM, as a percentage from <var>0</var> to <var>100</var> (not a currency amount). Defaults to the Customer's margin. |
| `targeting` <br /><span class="type-text">object</span> <span class="required-text">required</span> | Plan targeting. See [Political Planner resource properties](/political-vertical/planner#political-planner-resource-properties) for all targeting fields. |
| `targeting.whiteListedLocation.country` <br /><span class="type-text">integer</span> | [Country ID](/guidelines/master-api#get-country-segment) to target |
| `targeting.device.deviceTypeIds` <br /><span class="type-text">array of integers</span> | [Device type IDs](/guidelines/master-api#get-device-type) to target |
| `targeting.creative.creativeTypeIds` <br /><span class="type-text">array of integers</span> | [Creative type IDs](/guidelines/master-api#get-rtb-creative-types) to target |
| `cva` <br /><span class="type-text">object</span> | Custom Voter Audience to target, for example <var>&#123;"id": 12345&#125;</var>. See [Target a Custom Voter Audience](#target-a-custom-voter-audience). |

:::info

The plan's time zone is always set to your Organization's time zone. Any <var>timezoneId</var> value in the request is ignored.

:::

:::caution

The forecasting service decides which targeting and budget combinations can be planned, and there is no fixed list of valid combinations. A plausible request can still be rejected with <var>No strategies meet your criteria. Edit the plan to explore more options.</var> If this happens, nothing is created: widen the targeting or change the budget and try again.

:::

## Voter TV+ proposals

Voter TV+ (objective <var>3</var>) plans forecast reach across linear TV and connected TV (CTV). They follow a different path from the standard steps above:

1. Get a reach saturation graph
1. Create a ready plan with the graph
1. Activate the plan into a proposal
1. (Optional) Split the proposal's CTV campaigns
1. Generate an IO and campaigns, as in [Step 6](#step-6-generate-an-io-and-campaigns)

Voter TV+ plans must have a flight of 7 to 31 days and a budget over <var>100</var>. They can't target [Power Segment audiences](/political-vertical/audience-segments#power-segment-audience-details); requests that include one are rejected with <var>Power Segment audiences are not supported for Voter TV+</var>. When the IO is generated, only the CTV proposed campaigns become campaigns; linear TV campaigns are not created.

## Target a Custom Voter Audience

A Custom Voter Audience (CVA) combines voter segments into a single audience for a plan. Create the CVA first, then pass its <var>id</var> in the <var>cva</var> field when you [create a ready plan](#step-2-create-a-ready-plan).

### Create CVA details

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/plan/political/cva-details" operationId="createCvaDetails" />

<div class="endpoint-container">
  <div class="child1">

Define the CVA with an equation of voter segment IDs. Get segment IDs from [Get Custom Voter Audience segment details](/political-vertical/audience-segments#get-custom-voter-audience-segment-details) in the Audience API.

Equation syntax:
  * Wrap each segment ID in parentheses
  * Separate segments with <var>|</var> to combine them (OR)
  * Separate groups with <var>&</var> to intersect them (AND)

For example, <span class="code-text">((IQMCVACA069112|(IQMCVACA080323))&(IQMCVACA101616))</span> targets voters in either of the first two segments who are also in the third.

| Request schema |  |
| ---- | --- |
| `equation` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Segment equation |
| `stateIds` <br /><span class="type-text">array of integers</span> | [State IDs](/political-vertical/audience-segments#get-available-states-for-custom-voter-audiences) to limit the audience to; leave empty for all states |
| `reach` <br /><span class="type-text">integer</span> | Audience reach. This value is stored and passed to the forecasting service as provided; it isn't calculated. Use [Get CVA reach](/political-vertical/audience-segments#get-cva-reach) to get it. |

## Restore an expired proposal

<CopyUrl method="PATCH" url="https://api.iqm.com/api/v3/plan/political/proposals/restore" operationId="restoreProposals" />

<div class="endpoint-container">
  <div class="child1">

A proposal that isn't converted becomes <var>Expired</var> (<var>3</var>) after its end date passes. This happens on a schedule; there's no API call to expire a proposal. To use an expired proposal again, restore it with new flight dates. Restored proposals return to <var>Ready</var> (<var>6</var>) status and can then be converted as in [Step 6](#step-6-generate-an-io-and-campaigns).

Restoring only works on expired proposals. It isn't an undo for [Delete proposals](/political-vertical/planner#delete-proposals).

| Request schema |  |
| ---- | --- |
| `proposalIds` <br /><span class="type-text">array of integers</span> <span class="required-text">required</span> | IDs of expired proposals to restore |
| `startTime` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | New Unix epoch start time in milliseconds; can't be in the past |
| `endTime` <br /><span class="type-text">integer</span> <span class="required-text">required</span> | New Unix epoch end time in milliseconds; must be at least 30 minutes after <var>startTime</var> |
