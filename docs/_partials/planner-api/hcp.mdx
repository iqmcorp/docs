### Targeting consistency rule

The <var>selectedValueIds</var> in each <var>splitStrategy</var> entry must agree with the plan's targeting for that dimension. The creative type split must exactly match the plan-level creative types. The other dimensions must be a subset of the matching targeting.

The rule is checked when you create a plan (ready or draft), edit it, or publish it. [Generate campaigns plan](#generate-campaigns-plan) doesn't check it: it ignores <var>selectedValueIds</var> and splits by every plan-level value of each listed dimension. Campaign targeting isn't checked against the split strategy, so use the campaigns that generate campaigns returns.

### Publish campaigns plan

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/plan/hcp/campaigns/publish" operationId="generateIOCampaigns_2" />

<div class="endpoint-container">
  <div class="child1">

Publish an HCP plan to create an IO and campaigns. Send the full plan with its <var>id</var> and current <var>statusId</var>. Publishing first saves the request body with the same checks as [Update HCP Planner](#update-hcp-planner), so the same request rules apply. Only Advertiser Organizations can publish plans.

Publishing is asynchronous. The plan moves to <var>Processing</var> (<var>5</var>) while the IO and campaigns are created, then to <var>IO Created</var> (<var>7</var>), with <var>ioId</var> and each campaign's <var>campaignId</var> set. The response only confirms that publishing has started: use [HCP Planner details by ID](#hcp-planner-details-by-id) to check the result.

The campaigns are created as drafts. They don't run until creatives are attached and the campaigns are approved.
