### Get Custom Voter Audience segment details

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/audience/cva/segments" operationId="getSegmentDetails" />

<div class="endpoint-container">
  <div class="child1">

Browse the Custom Voter Audience segment catalogue to find segments to reference in a CVA <var>equation</var> (see [Create CVA Details](/political-vertical/planner/#create-cva-details)).

The catalogue is a tree. Only leaf segments (<var>isLeaf: true</var>) carry a real, non-zero reach and are valid to reference in an equation. Category/grouping nodes (states, topic groupings, etc.) always report <var>reach: 0</var> and exist only to organize the tree. A leaf segment's <var>taxonomyId</var> (e.g. <var>IQMCVACA041742</var>) is the exact token to use inside an equation string.

This endpoint fetches the segments based on the search parameters provided:
  * If no parameters are provided, it fetches all root segments for the whole country (currently U.S.) along with their child segments.
  * If only state IDs are provided, it fetches all root segments for those states along with their child segments.
  * If a parent segment ID is provided, it fetches all child segments for that parent segment — this is how you drill down the tree to find leaf segments.
  * If search keywords are provided, it fetches all leaf segments matching those keywords in the path key and description.
  * If taxonomy IDs are provided, it fetches all leaf segments matching those taxonomy IDs. If the <var>validateTaxonomyIds</var> flag is true, it validates that all taxonomy IDs exist.
  * If segment IDs are provided, it fetches those segments.
  * If valid supplied search criteria match no segments, it returns an empty list.

| Request schema |  |
| --- | --- |
| `stateIds` <br /><span class="type-text">array of integers</span> | List of state IDs used to fetch root segments for those states along with their child segments. |
| `parentSegmentId` <br /><span class="type-text">integer</span> | Parent segment ID used to fetch child segments for that parent — use this to drill down the tree. |
| `searchField` <br /><span class="type-text">string</span> | Comma-separated search keywords used to fetch leaf segments matching those keywords in the path key and description. |
| `taxonomyIds` <br /><span class="type-text">array of strings</span> | List of taxonomy IDs used to fetch leaf segments. |
| `validateTaxonomyIds` <br /><span class="type-text">boolean</span> | Flag to validate if all taxonomy IDs provided exist, default: <var>false</var>. |
| `segmentIds` <br /><span class="type-text">array of integers</span> | List of segment IDs used to fetch segments. |
| `pageNo` <br /><span class="type-text">integer</span> | Page number. |
| `noOfEntries` <br /><span class="type-text">integer</span> | Number of entries per page. |

### Create Custom Voter Audience

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/audience/cva" operationId="createCustomVoterAudience" />

<div class="endpoint-container">
  <div class="child1">

Create a Custom Voter Audience by providing audience details in the request body. The response includes the created audience ID which can be used to retrieve audience details and apply the audience to campaigns.

Using segment IDs (from the [Master API](/guidelines/master-api)), you can build an audience with the <var>equation</var> field. Segment IDs in parentheses, separated by a vertical bar (|), will be in an 'or' relationship, which will combine the sets of segments; groups of segments in parentheses, separated by an ampersand (&), will be in an 'and' relationship, which will build an audience based on the intersection of those groups. 

You can see an example of this format in the "Request sample" code block on the right-hand side of the page, or you can read more in our Help Center article on [Segments Groups and Relationships<ExternalLink />](https://help.iqm.com/en/articles/5651486-segmented-audience-overview#h_31da47f45c).
