### Power Segment audience details

<CopyUrl method="GET" url="https://api.iqm.com/api/v3/audience/power-segment/{audienceId}" operationId="getPowerSegmentAudience" />

<div class="endpoint-container">
  <div class="child1">

When <var>includeInsight</var> is <var>true</var>, each standard (public) segment includes its Insights status. <var>Ready</var> and <var>NotRequested</var> are returned as stored; <var>Processing</var> and <var>Failed</var> are returned as <var>NotRequested</var> unless the audience's Organization has requested the Insights report for that segment. ### Create Power Segment audience

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/audience/power-segment" operationId="createPowerSegmentAudience" />

<div class="endpoint-container">
  <div class="child1">

Create a Power Segment audience.

Using taxonomy IDs ([List/search Power Segments](#listsearch-power-segments)), you can build an audience with the <var>equation</var> field. Taxonomy IDs separated by a vertical bar (|) are in an 'or' relationship, which combines the sets of Power Segments. Wrap the group of taxonomy IDs in a double set of parentheses. Every taxonomy ID must belong to an active segment that is either a standard segment or private to the logged-in Organization.

You can see an example of this format in the Request sample code block on the right-hand side of the page, or you can read more in our Help Center article on [Segments Groups and relationships<ExternalLink />](https://help.iqm.com/en/articles/5651486-segmented-audience-overview#h_31da47f45c).

| Request schema | |
| --- | --- |
| `audienceName` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Audience name. |
| `equation` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Equation string representing the taxonomy ID group in an OR relationship. |

### List/search Power Segments

<CopyUrl method="POST" url="https://api.iqm.com/api/v3/audience/power-segment/segments/search/list" operationId="getPowerSegmentSearchList" />

<div class="endpoint-container">
  <div class="child1">

Search and filter Power Segments. 

The <var>individual</var> tab shows active standard segments plus the logged-in Organization's private active segments; the <var>requested</var> tab shows only the logged-in Organization's private segments that are active, requested, or failed. Favorite status is resolved for the logged-in user.

Each Sphere/Orbit segment of a standard segment includes its Insights status. It's returned only to users whose profile has the Power Segment Insights feature; for other users, <var>insights</var> is omitted.

| Request schema | |
| --- | --- |
| `pageNo` <br /><span class="type-text">integer</span> | Page number of retrieved data. |
| `noOfEntries` <br /><span class="type-text">integer</span> | Number of entries returned per page. |
| `sortBy` <br /><span class="type-text">string</span> | Sorts by ascending (<var>+</var>) or descending (<var>-</var>), e.g. <var>+personalityName,-category</var>. |
| `searchField` <br /><span class="type-text">string</span> | Search personalities by name. |
| `tab` <br /><span class="type-text">string</span> <span class="required-text">required</span> | Tab being viewed: <var>individual</var> or <var>requested</var>. |
| `favorite` <br /><span class="type-text">boolean</span> | When <var>true</var>, restricts results to personalities favorited by the logged-in user. |
| `categories` <br /><span class="type-text">array of strings</span> | [Power Segment category type](#power-segment-category-type-list) names to filter by, e.g. <var>CABINET_MEMBERS</var>. |

| `visibilityScope` <br /><span class="type-text">string</span> | Restricts results by visibility: <var>public</var> returns only standard (public) segments, and <var>private</var> returns only the logged-in Organization's private segments. When omitted or empty, no visibility filter is applied. Doesn't affect <var>totalRecords</var>. |
